# Mobile conventions (built by phase 04; 05/06 must follow)

- Toolchain: `export PATH=$HOME/flutter/bin:$HOME/jdk/bin:$PATH JAVA_HOME=$HOME/jdk ANDROID_HOME=$HOME/android-sdk`. Flutter 3.47.5. All deps already in `pubspec.yaml` (never edit): supabase_flutter, flutter_riverpod, go_router, google_sign_in 7, local_auth, flutter_secure_storage, device_info_plus, shared_preferences, intl, url_launcher, share_plus, image_picker, app_links, fl_chart, cached_network_image, firebase_core/messaging, mobile_scanner, webview_flutter; dev mocktail, integration_test.
- Routes: each feature exports a list in `lib/features/<f>/<f>_routes.dart` (`homeRoutes /home`, `vouchersRoutes /vouchers`, `walletRoutes /wallet`, `rewardsRoutes /rewards` are tab branches; `linkRoutes, searchRoutes (/search, /search/results), compareRoutes, priceHistoryRoutes, watchlistRoutes, ordersRoutes, withdrawRoutes, pinRoutes, missingOrderRoutes, kycRoutes, notificationsRoutes` are full-screen). Replace the `PlaceholderPage` builders inside your own list; keep exported names; `app/router.dart` already registers them.
- Paths: `lib/app/route_paths.dart` → `RoutePaths.*` + helpers `linkFor(id), compareFor(id), priceHistoryFor(id), orderDetailFor(id), pinFor(mode), kycStep(n)`, `RoutePaths.pinVerifyReturnPin`.
- PIN contract (06): `/pin?mode=verify&return=pin` calls `verify_pin` then `context.pop(pinString)`; `/pin?mode=verify` issues a pin_token for withdraw; `/pin?mode=create|change`. Account already pushes `/pin…`, `/kyc`, `/kyc?step=2`, `/missing-order`, `/notifications`.
- Providers (`core/...`): `supabaseProvider, authSessionProvider, currentUserIdProvider, isSignedInProvider`; `profileProvider` (Profile: isLocked, hasPin, withdrawalHoldUntil, shownName, notificationPrefs), `isAccountLockedProvider`, `walletProvider` (live Wallet: availableVnd, pendingVnd, heldVnd, awaitingVnd, totalEarnedVnd), `unreadNotificationsProvider`, `merchantsProvider` (Merchant: domains, badgeLetter, datafeedEnabled…), `maxRateBpsProvider`, `deviceIdProvider` (String for create-link device_id), `sharedPreferencesProvider` (override in tests), `biometricPinVaultProvider` (isSupported/isEnabled/enable(pin)/disable/readPinWithBiometric), `realtimeEventsProvider` (emits 'orders' | 'notifications' | 'withdrawals' | RealtimeService.resync → `ref.invalidateSelf()`).
- FCM: `core/device/push_token_service.dart` already upserts tokens when `FCM_ENABLED=true`; 06 reuses it (foreground message display only).
- Errors: `core/supabase/postgrest_error_mapper.dart` → `mapErrorMessage(e)`, `errorCodeOf(e)`, `AppFailure.from(e)` (.code/.detail map/.message), `errorMessagesVi`.
- Utils: `formatVnd, formatVndCompact, formatDayMonth, formatDate, formatDateTime, stripDiacritics, normalizeName`. Widgets `core/widgets/`: `AppTopBar, AppButton(kind, loading), AppCard, MoneyText, MerchantBadge, StatusPill(.forStatus), FilterChipBar<T>, SectionHeader, AsyncValueView, EmptyState, ComingSoonBadge, ProductTile, BalanceSummaryCard, PlaceholderPage`. Theme `AppColors, AppText, AppRadius`.
- Backend: user tables `orders`, `withdrawals`, `wallet_ledger` have column-level grants → always `.select('col1,col2,…')`, never `*` (see backend-contracts.md). Edge calls via `supabase.functions.invoke`.
- Env: `env/example.json` via `--dart-define-from-file`; Turnstile widget `features/auth/presentation/widgets/turnstile_captcha.dart`.
- Sign-out/vault: `AuthController.signOut` cleans up in order (push token row + FCM `deleteToken`, biometric vault, pending referral) then `signOut`; each step is best effort. `sessionCleanupProvider` also wipes the vault/referral when the session ends remotely. **The PIN screen (06) must call `biometricPinVaultProvider.disable()` after `set_withdraw_pin` change/reset** (stored PIN goes stale and burns `pin_locked` tries); account already does it before opening `/pin?mode=change`. The vault is an app-level gate only (server `verify_pin` is authoritative).
- Grants trap: never `.count()` or `.select()` bare on `orders`/`withdrawals`/`wallet_ledger`; use `.select('id').count(CountOption.exact)` / explicit columns.
- Referral: `/r/<code>` binds immediately when signed in (`bindPendingReferral`), else is stored until login; cleared on sign-out.
- Ids: applicationId/bundle id is `io.canhgia.app` (spec text said `vn.canhgia.app`; kept to match supabase config). No custom URL scheme (App Link `https://<APP_LINK_HOST>/r/` only). iOS needs `GOOGLE_IOS_CLIENT_ID`, `GOOGLE_IOS_REVERSED_CLIENT_ID`, `APP_LINK_HOST` set in `ios/Flutter/*.xcconfig` (unverified, no macOS).
